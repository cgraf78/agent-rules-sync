# AGENTS.md

## About

`agent-rules-sync` is a Bash provider that renders caller-owned rule
fragments and a playbook index into managed blocks in agent rule files. It
reads only the files a manifest lists: it never scans `$HOME`, chooses policy,
evaluates shell from configuration, or ships real rule prose. Ownership
rationale is in [`docs/design.md`](docs/design.md); the user contract is the
README.

## Layout

- `bin/agent-rules-sync` is the only public command.
- `lib/agent-rules-sync/` is private and version-coupled to the launcher:
  `api.sh` (sync/check/uninstall sequencing), `manifest.sh` (parse and
  validate), `render.sh`, `targets.sh` (built-in target table), `managed.sh`
  (block ownership), `lock.sh` (`mkdir` lock), `migration.sh` (target state
  and dot-era takeover), `paths.sh`, and `temp.sh`. See its `README.md`.
- `examples/` is a synthetic setup; `test/cli-test` renders it, so keep it
  valid.
- `support/install-checkout.sh` is the repo-owned install delegate that the
  generated `install.sh` calls.

## Invariants

- Validation and rendering finish before any destination is modified.
- Text outside `# agent-rules-sync:aggregate begin/end` is preserved.
- Targets are written atomically with mode `0600`.
- `check` mutates nothing: no target, parent directory, lock, or state.
- Exit codes: 0 ok, 1 invalid input or IO error, 2 usage, 3 drift (`check`
  only).
- Bash 4.0+ (associative arrays).
- A new built-in target means updating `targets.sh`, the README Targets
  table, and `test/provider-test` together.

## Testing

- Local: `test/run` runs every suite, then ShellCheck over
  `.github/shellcheck-files.txt` when `shellcheck` is on `PATH`.
- CI: `AGENT_RULES_SYNC_SKIP_SHELLCHECK=1 test/run` on the shared full matrix
  (Linux, macOS, Termux; profile `base`). ShellCheck runs as a separate shared
  job.
- `test/run` hard-codes its five suites (`cli-test`, `provider-test`,
  `managed-test`, `check-test`, `install-test`). A new suite is never run
  until you add it there and to `test/README.md`.

## Test isolation

- `test/lib/test.sh` unsets `XDG_CONFIG_HOME`, `XDG_DATA_HOME`,
  `XDG_STATE_HOME`, and `XDG_CACHE_HOME`, and suites build fixtures under a
  validated temp root.
- Fixtures are synthetic and must never read or write real `~/.claude`,
  `~/.codex`, or other installed agent targets.

## CI and generated files

- CI's ShellCheck job fails on any shell program missing from
  `.github/shellcheck-files.txt` (untracked files included) and on stale rows;
  local `test/run` does not detect this. Before pushing, run
  `bash <actions@lock>/.github/actions/shellcheck-inventory/run.sh "$PWD" .github/shellcheck-files.txt`.
- `install.sh` is generated by cgraf78/actions checkout-installer and
  byte-checked by `actions-sync`. Edit `scripts/checkout-installer.conf`, then
  run `consumer-ci/sync.sh <this checkout>` from cgraf78/actions at the locked
  SHA.
- `.github/cgraf78-actions.lock` and every `uses: cgraf78/actions/...@sha`
  move together, only via `consumer-ci/sync.sh`. Dependabot ignores
  `cgraf78/actions` for this reason.
- `retry-infrastructure.yml` keys on the workflow name `Tests`; don't rename
  it.
